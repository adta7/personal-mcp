Most sites that claim to be "API-accessible" are a website plus a bolted-on `/api` folder that
drifts out of sync within a month. This one is built so drift is structurally impossible:
`content/` holds the facts, `src/core/` resolves them, and the website, the JSON API, and the
MCP server are three thin adapters over the same resolver functions. The dependency direction
is enforced by a lint rule rather than by discipline, and a parity test asserts that all three
surfaces derive from the same call.

There is no database. Content is typed files in git, validated by Zod at build time, so
malformed data fails CI instead of throwing in production. The same schema definition produces
the TypeScript types, the content validator, the OpenAPI document, and the MCP tool input
schemas.

Add it to a client:

```
claude mcp add --transport http albert https://albertyan.dev/mcp
```
